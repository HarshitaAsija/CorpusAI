# n8n Enterprise Approval Workflow Setup Guide

This guide explains how to set up, import, and test the **n8n Human Approval Workflow** for CorpusAI. When `APPROVAL_BACKEND=n8n` is set in `orchestrator/.env`, medium and high-risk decisions trigger this workflow to request human sign-off via Slack or Email and resume the CorpusAI state machine instantly via webhook callback.

---

## 📋 Prerequisites

1. An **n8n** instance (Cloud at `https://your-instance.app.n8n.cloud` or self-hosted via Docker).
2. A **Slack Bot Token** (`xoxb-...`) with permissions `chat:write` or Slack App credentials configured in n8n.
3. A publicly accessible URL or tunneling service (e.g., `ngrok`) for your local CorpusAI orchestrator server (`http://localhost:3000`).

---

## 📥 Step 1: Import the Workflow into n8n

1. Open your n8n canvas dashboard.
2. Click on **Workflows** ➔ **Import from File** (or top-right menu `...` ➔ **Import from File**).
3. Select the file:
   `orchestrator/n8n/corpusai-approval-workflow.json`
4. The canvas will load three connected nodes:
   - **Webhook Trigger (CorpusAI)**
   - **Post Slack Approval Request**
   - **HTTP Callback to CorpusAI Orchestrator**

---

## ⚙️ Step 2: Configure Credentials & Node Settings

1. **Slack Node Credentials**:
   - Double-click the **Post Slack Approval Request** node.
   - Select or create a new Slack API credential using your `xoxb-...` Slack Bot token.
   - Set the target channel (e.g., `#general` or your `SLACK_CHANNEL_ID`).

2. **Webhook Trigger Node**:
   - Double-click **Webhook Trigger (CorpusAI)**.
   - Set HTTP Method to `POST`.
   - Copy the **Test Webhook URL** and **Production Webhook URL** generated by n8n.
     Example: `https://your-n8n-instance.app.n8n.cloud/webhook/corpusai-approval`

3. **Activate Workflow**:
   - Toggle the workflow state switch at the top right of the n8n canvas from **Inactive** to **Active**.

---

## 🔑 Step 3: Update `orchestrator/.env` Configuration

In your `orchestrator/.env` file, configure the following variables:

```env
# Enable n8n Approval Backend
APPROVAL_BACKEND=n8n

# Webhook URL copied from your n8n workflow canvas
N8N_APPROVAL_WEBHOOK_URL=https://your-n8n-instance.app.n8n.cloud/webhook/corpusai-approval

# Public URL of your orchestrator server for callback response (e.g. via ngrok)
PUBLIC_BASE_URL=https://your-ngrok-subdomain.ngrok-free.app

# Shared secret for signing & verifying callback payloads
WEBHOOK_SHARED_SECRET=your-secure-webhook-secret
```

## 🧪 Step 4: End-to-End Verification Test

### Option A: Manual Webhook Simulation via `curl`

To verify that n8n can successfully send an approval callback to CorpusAI:

```bash
curl -X POST "http://localhost:3000/webhooks/approval" \
  -H "Content-Type: application/json" \
  -H "x-webhook-secret: your-secure-webhook-secret" \
  -d '{
    "decisionId": "test-dec-123",
    "initiativeId": "test-init-456",
    "status": "Approved",
    "decidedBy": "Human Manager (via n8n Manual Test)"
  }'
```

**Expected Response in Terminal**:
```json
{
  "success": true,
  "message": "FSM resumed via n8n approval webhook"
}
```

### Option B: Full FSM Trigger Test

1. Start your orchestrator server:
   ```bash
   cd orchestrator
   npm run dev
   ```
2. Trigger a high-budget initiative ($9,500) via the UI dashboard or API endpoint:
   ```bash
   curl -X POST "http://localhost:3000/api/initiatives/trigger" \
     -H "Content-Type: application/json" \
     -d '{ "goal": "Launch $9500 Enterprise Ad Campaign", "owner": "Marketing Lead" }'
   ```
3. Observe console logs:
   - `[FSM] Adaptive Autonomy Engine returned Medium/High risk.`
   - `[FSM] Dispatching human approval request to n8n webhook...`
   - Slack receives notification.
   - n8n triggers callback to `/webhooks/approval` and instantly resumes FSM execution to state `Executing`.
